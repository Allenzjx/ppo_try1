# Block12 第一次更新的 FL 捕获信用分配

只读范围：已封存 run 20260918T0909562623513Z_g3a50657a96c9_d0f934ba1eae46958f7c8b880fdac987，update 1400 的首 128 个 learner 样本（183553–183680）、rollout_001400.pt 与 20 条真实 minibatch hooks。没有读取活动 block13、额外 actor forward、optimizer replay 或物理运行。

## 结论

没有发现本范围内的 reward 符号、存储对齐或概率路径错误；但“发生捕获”没有自动得到正的归一化优势。捕获附近出现明确的相对信用冲突：捕获和前两拍下降的即时奖励均为正，normalized advantage 却为负。本次最后一次被观察到的 minibatch 使用中，FL hip/knee conditional mean 仅微幅向捕获样本靠近；该捕获样本联合概率的净增加主要来自其他 10 通道，不是 FL hip 均值学到了捕获动作的证明。

这是当前整批相对优势和共享参数更新的实际结果，不足以据此认定 PPO 实现有 bug，也不能据这一批决定应改 reward 或创新 σ。

## 接线与范围核验

raw、reward、reward families 总和、old μ/σ/logp 与保存 storage 逐位一致；hook old logp/advantage 与保存值一致；128 个样本各被使用5次。P05→P06 不切 done；prefix 未入 storage。首未更新 minibatch 最大 |ratio−1|=1.967e−6；归一化最大误差2.384e−7；127条内部 GAE 递推最大误差1.729e−6。独立逐通道高斯 logp 求和与实际联合 hook 差异最大4.464e−6，符合浮点误差。

这些是实际完成 update1400 的证据，不是最终 CP183680 的分布复测。没有保存末尾 bootstrap value，未伪造尾部递推；没有最终 actor forward，因此不能声称保存 checkpoint 的均值已改善，也不能把全身下降归因于单个 hip。
