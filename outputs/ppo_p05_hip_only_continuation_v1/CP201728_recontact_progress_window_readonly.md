# 再接触进度窗口：只读核验

当前训练不变；没有修改生产代码、控制配置或 Isaac 进程。以下合成测试仅调用当前 Python 控制类，非物理仿真、非 PPO 样本。

## 实现问题成立，但本条 CP201728 没触发它

`semantic_capture_assist.py` 的实际接触分支每拍将 `window_start_gap_m` 设置为接触时 gap，并将 `window_elapsed_s` 清零。随后 HOLD→无障碍接触时，不会以本次重新打开的 gap 重建进度基准。因此接触 gap 为 −1 mm，重新悬空后 gap 从 +10 mm 持续减到 +6 mm，仍不能达到旧基准要求的 −1.2 mm，最终会报 `gap_not_improving`。问题不限于负接触 gap；接触时 +0.5 mm、丢失后 +10→+6 mm 也会发生。

这会把“尚未回到上次接触高度”误作“本次再接近没有改善”，是局部进度基准的实现问题，不能证明某条实际轨迹一定可由继续下降挽救。
