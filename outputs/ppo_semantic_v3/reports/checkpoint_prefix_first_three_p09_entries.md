# Checkpoint-policy P06 prefix：前三回合 P09 入口固定窗口

## 范围与结论

只审计训练 run `20260906T2211507063967Z_ga580fc2add81_e539358648084c70bf6b28037515480c` 已保存的 **global 84993–86016，1024 个 PPO 决策，update 630–637**。三结束回合共 959 决策，另 65 决策是 episode 3 的非终止 P06 尾段，不能列作第四次失败。没有使用后续增长记录。

三回合都经过连续 P06→P07→P08→P09，在 P09 入口后 0.625–0.725 s 发生记录明确的 `BODY_COLLISION`；尚无 RR hard qualified/cross/placed。这不是课程初始化失败，也不是截止时间未完成。有效传感数据 `physical_evaluator.valid=true` 与真实任务碰撞失败不矛盾。

对照是源 checkpoint C84992 的**固定 mean、天然 P01**完整评估 `20260906T2132007864973Z_ge99fde1b3e83_62520cdf88e549ae9929b9916bd92336`。它后来确实取得 RR Q7149/C7184/P7191，但最终仍为 90.2 s、1353 决策、10824 ticks 的 `INCOMPLETE_CONTROLLER_BLOCKED`，不是完整任务成功。新训练是 C-checkpoint prefix 后的随机 PPO，且发生在线更新；它与源评估不是配对同策略同状态实验。

**主要证据边界：FL AIR、RR 仍接近地面、前送/抬 FL 建议本身并不足以区分这三次早期碰撞与源 C 后续成功抬 RR。** 训练紧凑日志缺完整 base/CoM/关节状态和原始碰撞 pair，因此本窗口不能确定哪个姿态或载荷因素造成碰撞，也不能据此设置历史入口姿态门。

## 可证实与尚不可识别

证实：连续交接和即时 native 控制生效；建议/残差都有实际目标体现；前三次在 RR hardQ 之前真实失败；FL 历史 placed 与当前 AIR/零载荷严格分开。当前 capture 新 branch 需要 RR Q+C，这三回合没有激活它的前提，不能用这些回合判断该 branch 对 RR 放置的效果。

未证实：哪种 body 姿态、CoM 方向、接触点、反馈补偿、动作随机性或相位内执行组合导致早碰撞；也未证实执行权限缺失或单一 reward 冲突。数据不支持修复/调参决定、固定入口姿态/支撑/AIR门、或把停止优化直至成功当成新门禁。

读取方法：训练严格固定1024行，未读取后续 tail。首次同窗口处理在 JSON 序列化阶段因整数 hashtable keys 失败；经根代理授权，仅对相同84993–86016重读一次并改字符串keys，保留其为工具处理失败，不是运行失败。评估只保留6480/6488/6496/6560和7149/7184/7191附近端点。无 Python、CUDA、Isaac、新仿真、模型加载、生产改动或重复大文件 hash。报告完成后停止。
